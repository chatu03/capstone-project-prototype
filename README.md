# ConstructWaste

A final-year proposal presentation prototype for an **AI-Based Construction Waste Prediction and Management System** for residential construction in Zambia.

## Open the prototype

Open [construction-waste-prototype/index.html](construction-waste-prototype/index.html) directly in a modern browser. No server, installation, npm, internet, API keys, or external assets are required. Keep `index.html`, `style.css`, and `script.js` in the same folder.

The five sidebar modules are Dashboard, Projects, Waste Prediction, Waste Recommendations, and Reports. The application uses HTML, CSS, and vanilla JavaScript only.

## A short presentation walkthrough

1. **Dashboard:** explain the fictional sample projects and eight sample simulations. Material waste is shown in each material's own unit; incompatible units are never added together. Bars show waste as a share of that material's planned quantity, with a separate scale for each row.
2. **Projects:** add a residential project, enter its location and floor area, and choose a construction stage. Projects can be edited and deleted with confirmation.
3. **Waste Prediction:** choose the project and stage. Roofing offers roofing sheets and timber; foundation offers cement, sand, aggregates, steel, timber, and quarry dust. Enter a quantity and select **Predict Waste**. For example, 200 cement bags at the fictional 5% rate yields 10 bags of waste and 190 usable bags.
4. **Waste Recommendations:** select a material to see predefined guidance for handling, storage, planning, and reuse.
5. **Reports:** choose a saved simulation and select **Print Report**. The browser can print it or save it as a PDF. Printed reports include the simulation disclaimer.

**Reset demonstration data** restores the three fictional projects and eight sample simulations after confirmation. It removes all user-entered prototype data. Sample dates are the dates the samples were created/reset; displayed dates use Zambia time.

## How the code works

- `index.html` provides the semantic structure, five module sections, labelled forms, sidebar, and report container.
- `style.css` defines colours and spacing, responsive cards, mobile navigation, charts, and print rules. Icons are inline SVG; typography uses locally available system fonts.
- `script.js` holds the material catalogue, stage mapping, fictional waste rates, predefined recommendations, storage, and interface functions. Comments identify each main responsibility.

Key JavaScript functions:

| Function | Responsibility |
| --- | --- |
| `showPage` | Shows a module and updates navigation, browser hash, and page title. |
| `loadData`, `saveData` | Seed samples once and read/write localStorage. Empty arrays remain empty. |
| `openProjectForm`, `deleteProject` | Populate project forms and confirm deletions. The form submit handler validates and saves projects. |
| `filterMaterials`, `updateUnit` | Filter by stage and update the unit, quantity step, and illustrative rate. |
| `calculateWaste` | Apply the percentage from `WASTE_RATES`; round piece counts and calculate the usable remainder. |
| `renderDashboard` | Update counts, per-material summaries, charts, and recent records. |
| `renderRecommendations` | Show predefined guidance for the chosen material. |
| `renderReport` | Show an original project snapshot and simulated quantities for a saved record. |

The `WASTE_RATES` object is the single editable source of illustrative percentages. Waste is `planned × rate ÷ 100`. Pieces round to the nearest whole piece. Other quantities use two decimal places; usable quantity is the planned quantity minus rounded waste. The actual percentage after rounding is shown separately from the predetermined illustrative rate. Small piece quantities may therefore produce zero waste. Cement stays in 50 kg bags, with the optional kilogram equivalent shown in results and reports.

All eight catalogue materials are represented: cement, building sand, crushed stones/aggregates, concrete blocks/bricks, reinforcement steel, timber, quarry dust, and roofing sheets.

## Storage and limitations

Data stays in this browser using the `constructwaste-prototype-v1` localStorage key. Deleting or editing a project preserves historical simulation reports with their original project details. Clearing browser data removes saved projects and simulations. File-based storage behaviour varies between browsers; use the same browser and file location for the presentation. If storage is blocked or saved data is unreadable, an explicit warning appears and the application runs temporarily in memory. Unreadable stored data is not overwritten without a confirmed reset. No data is sent anywhere.

**DEMONSTRATION ONLY: These results are simulated and are not generated by a trained AI model.**

The final proposed system will use a trained machine-learning model to estimate construction waste based on relevant project and material data. The rates and sample quantities here are fictional and are not scientifically established waste rates or measured Zambian site data. Recommendations are predefined rules, not AI-generated.

This is a preliminary interface and workflow prototype, not a completed Waterfall implementation. The approved final project will follow the Waterfall Software Development Model; dataset collection, database, backend, model training, and evaluation belong to later phases. Final model coverage will depend on available training data and may initially cover fewer materials.

## Validation

The prototype was exercised in headless Chromium with the browser context offline and local HTML/CSS/JavaScript supplied by the test harness at a localhost origin. This environment's managed browser policy blocks `file://` navigation, so direct-file opening must also be checked in your presentation browser. The application uses relative files and has no server requests or external dependencies.

Browser checks cover module navigation, sample seeding, project create/edit/delete, stage filtering, quantity validation, whole-piece and cement calculations, persistence across reloads, report snapshots, recommendation selection, reset/empty states, print styling and PDF output, and layouts at 375, 768, and 1440 pixels. Storage-denied and corrupt-storage fallbacks were checked separately. These are browser workflow checks, not validation of predictive accuracy.
